# Data Model

## Core model

The data model links three things:

1. champion data from the spreadsheet;
2. normalized draft state in memory;
3. strategic analysis generated by the engines.

## Relationships

- A champion belongs to one role slot in the draft.
- A draft contains up to five champions.
- The analysis consumes the draft and produces identity, tempo, plan, risks and guidance.
- The story layer turns that analysis into a coach-style summary.

## Normalization rule

Repeated values such as identity, function, tempo and tag-like labels should be normalized once and reused everywhere else.

## Implementation rule

The model should make the app easier to reason about, not harder. If a field does not help the analysis or the UI, it should not become part of the canonical shape.
